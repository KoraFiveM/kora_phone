# kora_phone agent guide

`kora_phone` is a server-authoritative FiveM phone for the Kora `[v2]` stack: physical handsets (Standard, Flip, Fold) as inventory items, removable SIMs, PIN and cloud backup, calls over kora_voice, messages, mail, camera and gallery, Pulse/Flash social, Market, and sandboxed third-party apps (iframe plus `@kora/phone-sdk`). It is Kora-only: no qb/ox/esx compat, apart from the custom-app alias exports (lb-phone, sd-phone, 17mov_Phone, yseries, high-phone). Layout: `fxmanifest.lua`; `config/` (`shared.lua` calls `Kora.config.define`, `handsets.lua` and `server.lua` use `Kora.config.extend`, `client.lua` is only a note; admins edit values with `/config`, which writes `config.local.lua`); `locales/` (`Kora.lang`); `shared/` (`constants.lua`, `validation.lua`, `contracts.lua`, and `routes.json`, the single route table read by the gateway, `client/nui.lua` and the web bundle); `client/` (NUI bridge, calls, camera, map, share, notifications, `integrations/voice.lua`, `sdk/` registry and events, `customapps.lua` with the alias exports); `server/` (`schema.lua` via `Kora.sql.ensureTables`, `repositories/` (all SQL), `services/`, `integrations/` (kora_core, banking, jobs, voice, storage, database, schema setup), `handsets/` and `phone_commerce.lua` (handset lifecycle, SIMs, cloud, shop counters), `mail/system.lua`, `modules/*_callbacks.lua`, `callbacks.lua` (gateway) and `rate_limits.lua`, and `sdk/` (the app SDK server side, with its own `schema.lua`)); `sdk/` (the `@kora/phone-sdk` package); `examples/` (`hello-app`); `web/` (React 19, TypeScript and Vite NUI source in `web/src`, built into `web/dist`); `tests/` (Lua and Node checks plus a kora_qa feature file), `test/` (`run.sh` and the raw-print guard); `local-media/` and `docs/`. Run the whole suite with `LUA=lua5.4 bash test/run.sh` (see `tests/README.md`).

Stack rules: Kora-only. Use `kora_lib` (`Kora.callback`, `Kora.keybind`, `Kora.lang`, `Kora.logging`, `Kora.screenshot`, `Kora.config`), `kora_core` exports and events, `kora_sql` (`Kora.sql`, tables only through `Kora.sql.ensureTables`, no migrations), `kora_inventory` (`PhoneItemTransaction`), `kora_banking` (`ExecuteTransaction`), `kora_voice`, and `kora_theme` for every colour, font and shape in the NUI. Do not add qb, ox or esx compatibility; the only aliases are the custom-app exports.

## Documentation

User-facing documentation lives in `docs/` (Markdown, published via the Kora Docusaurus site, kora_docs_next). Read `docs/index.md` first for an overview and the documentation map. Layout: `index.md` (hub), `installation.md` (install steps, dependencies, optional resources, convars, updating), `how-to-use.md` (request pipeline, Wallet, Banking transfers, Marketplace, shops, custom apps), `commands.md` (commands, key mappings, interactions), `apps.md` (app SDK developer guide, sidebar position 5.5), `api/` (`index.md`, `exports-events.md`: client and server exports and phone-alias exports, and `apps.md`: SDK exports, routes and iframe protocol), and topic pages (`configuration.md`, `features.md`, `ui.md`, `three-handsets.md`, `events.md`, `permissions.md`, `items.md`, `database.md`, `media-storage.md`, `banking-jobs.md`, `community-security.md`, `system-mail.md`, `security.md`, `troubleshooting.md`, `acceptance-tests.md`, `roadmap.md`). `docs/api/_category_.json` positions the API folder at 5 in the sidebar; every page carries a unique `sidebar_position`. Update the page that owns the topic you changed.

When you add, change, or remove a feature, config option, command, export, event, item, permission, or database table/column, update the matching page in `docs/` in the same change. Keep docs accurate to the code; do not document behaviour that does not exist.

Docs rules: plain Markdown with `title`/`sidebar_position` front matter (no `id`/`slug`), relative links only between docs pages, assets inside `docs/`, fenced code blocks with a language, and no raw `<`, `>`, `{`, `}` outside code (pages are parsed as MDX). The release version comes from `fxmanifest.lua`'s `version` field.
